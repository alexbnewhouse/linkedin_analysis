# archetype_methods

A fresh survey of ways to assign career work archetypes, with a hand-labeled
gold set and a benchmark of every method on it. Written 2026-09-17 without
reference to the shipped `archetypes/` module or its earlier proposals.

| file | what |
|---|---|
| `METHODS.md` | the candidate methods: inductive (I1 to I3), deductive (D1 to D4), mixed (M1 to M5) |
| `EVALUATION.md` | gold-set protocol, metrics, cost, results, interpretation, caveats |
| `results/benchmark.md` | every table, generated by `bench.py` |
| `framework.py` | the director's nine-archetype framework, transcribed as data |
| `gold/` | the 400-role sample and its labels |

## The short version

The target label space is the colleague's deductive framework: nine skill
archetypes, each with an orientation, signature skills, and pathways of
representative titles, plus an explicit tenth label, "none", for work the
framework does not describe.

| finding | number |
|---|---|
| share of the population-weighted head the framework fits strongly / weakly / not at all | 45% / 30% / 25% |
| best method, a 27B local model reading the framework (D3) | 81% strict, 93% on strong-fit roles |
| best cheap method, a classifier bootstrapped from framework titles (M3) | 69% strict, 82% person-weighted |
| best pure deduction, nearest framework title in embedding space (D2) | 64% |
| framework structure recoverable from description clusters vs title clusters (I2 vs I1) | 54% vs 39% |
| people in title clusters a 27B model would not map to one archetype | 40% |

## Recommendation

Use a two-tier mixed pipeline, and publish the residual.

1. **27B zero-shot (D3) on the head that carries the population**: bands A
   and B, about 8,200 roles, about two hours on the Strix Halo, with primary,
   optional secondary, and "none". This is the accuracy ceiling and it is
   affordable where it matters.
2. **Bootstrapped classifier (M3) for the rest**, retrained with the D3 labels
   added to its seeds, abstaining below a probability floor, so the tail gets
   the head's judgment at no LLM cost. Expect the mid-70s on the tail once the
   seed set includes D3's labels; today, on framework titles alone, it is 69%.
3. **Keep "none" as a first-class outcome** and report its share. A quarter of
   the head is owners, founders, clinicians, trades, transport, uniformed
   service, and retail frontline work. The framework's author should see this
   list and decide whether a tenth archetype or a stated boundary is the right
   answer.
4. **Use the description clusters (I2) as the audit**, not the classifier.
   They are the one view that reads what people did rather than what they were
   called, and their k = 20 cards show where the framework's cuts disagree
   with the data (sales with general management and operations;
   administration with accounting).

What not to do: cluster titles and then name the clusters (M4), tune
abstention floors on embedding methods to buy precision (the trade is poor),
or use an 8B model (26 points below the 27B on the same prompt).

Before publishing any archetype share: a second annotator on the gold, the
framework's author on the weak-fit and none rows, and a measured bias for the
chosen method, because population shares differ by method (leaders is 10% of
people under one method and 29% under another).

## Running it

```bash
uv run python -m archetype_methods.gold sample          # already drawn; labels in gold/labels.csv
uv run --group embed python -m archetype_methods.m_deductive
uv run --group embed python -m archetype_methods.m_inductive   # I1, I2, I3; I2 embeds 172k descriptions (~5 min GPU)
uv run --group embed python -m archetype_methods.m_mixed       # reads deductive_assignments.npy for the vote
uv run python -m archetype_methods.bench_llm prepare-d3        # prompts for the LLM tiers; answers are ingested
uv run python -m archetype_methods.bench_llm ingest-d3 deep    #   from results/llm/d3_<tier>_batch_*.json
uv run python -m archetype_methods.bench                       # results/benchmark.md
uv run python -m archetype_methods.archetype_methods_tests
```

Embeddings (bge-base, on the 5080) are cached under `cache/` by content hash.
The LLM steps run through the local `local_delegate` server from the
orchestrating session; nothing leaves the two machines.

Inputs: `archetypes/results/role_features.parquet` (the per-role feature
aggregate, reused as the role universe), `normalized/career_steps.parquet`
(descriptions), `transition_network/role_edges.parquet` (mobility), and the
O*NET occupation descriptions in `reference/`.
